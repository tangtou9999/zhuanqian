# 赚钱 APP 产品需求文档（PRD）

版本：0.2（加入平台研究与大任务拆分模型）
定位：居家任务与灵活协作平台
口号：赚钱啦，赚钱啦！想要赚钱，就上赚钱 APP！

## 1. 产品目标
为希望在家获得额外收入的人群提供简单、可信、可理解的任务入口。平台组织任务供给、拆解与分发，用户按能力选择任务，按明确标准交付，经过公平验收后结算。不做传统综合招聘网站，不把求职、简历、职位搜索作为首页主流程。

## 2. 用户角色
- 个人用户：浏览任务、查看要求、领取任务、提交成果、按规则修改、查看收入。
- 企业客户：提交真实业务需求、确认报价与验收标准、验收交付成果。
- 平台运营：企业审核、任务审核、拆单、分发、质检、争议处理、对账。
- 质检/物流协作人员：对适用的线下批量加工任务进行抽检、收发与交接。

## 3. 用户端信息架构
底部固定四个入口：
1. 找任务：首页、任务分类、推荐任务。
2. 我的任务：待开始、进行中、待提交、待验收、待修改、已完成、争议中。
3. 我的收入：待验收金额、待结算金额、可提现金额、收入明细。
4. 我的：技能档案、身份认证、收款方式、帮助客服、安全须知。

任务分类初期：手工加工、AI办公、设计制作、文字整理、音视频、电商协作、数据任务。分类可由后台配置，不在客户端写死。

## 4. 任务详情必须展示
需求方主体及平台核验状态；任务内容、交付物、工作量；计价方式、报酬金额、结算条件；截止时间、预计耗时；所需技能和设备；操作步骤、图文/视频教程；验收标准、抽检规则；可修改次数、修改时限；争议与申诉入口；物流/材料交接说明（仅线下任务）。

## 5. 核心业务状态
草稿 → 平台审核 → 已发布 → 可领取 → 已领取 → 进行中 → 已提交 → 验收中 →（通过→待结算→已结算）/（退回修改→重新提交）/（争议处理）。
任务取消、超时、企业撤单、用户退出均需有独立状态和责任规则。所有状态变化必须记录操作者、时间和原因。

## 6. 企业任务与平台拆单
企业提交需求及样品/资料 → 平台核验主体和需求 → 明确总量、单价、质量标准、交期和资金保障 → 平台评估是否可拆分 → 创建子任务/工序 → 分配合适用户或小组 → 质检 → 汇总交付 → 企业验收 → 结算。
线下加工必须先完成小批量试单，核验单位工时、返工率、运输半径、材料损耗和实际净收入，再决定扩大规模。

## 7. 收入与结算
产品界面区分“预估报酬、待验收、待结算、可提现、已结算”，不得把未验收金额描述成已赚到的钱。平台不自行无资质沉淀或挪用用户资金；支付、托管、结算安排须由专业法律与支付合规评估确定。

## 8. 风险与安全
- 企业实名/主体核验和联系方式验证
- 需求真实性、预算与资金来源核验
- 禁止押金、垫资刷单、拉人头、虚假点赞评论、非法数据采集等任务
- 明示任务报酬、扣款规则和验收标准
- 企业拒收必须给出对应标准及证据
- 设置申诉、复核和人工客服
- 最小化收集个人信息，敏感信息加密并设置权限
- 防止未成年人从事不适宜任务
- 对可能构成劳动关系、劳务关系或承揽关系的模式分别评估，不能用产品名称替代法律判断

## 9. MVP范围
第一版真实业务只选择1-2个可远程验收、低风险、交付标准明确的任务类别（建议先验证PPT/文档整理或商品资料整理）。手工加工先作为后台验证中的候选业务，不在没有企业订单和物流方案时开放给用户。

## 10. MVP验收标准
新用户可在不看教程的情况下找到任务并理解报酬和要求；任务详情关键规则完整展示；领取、提交、退回修改、再次提交、验收、申诉状态闭环；每笔报酬可追溯到企业订单和资金来源；企业不能无理由无限退回；管理员可暂停企业、任务和用户；所有关键操作有审计日志；移动端主流浏览器可用，页面有空状态、错误提示和加载反馈。

## 11. 平台模式与任务拆解原则
参考猪八戒网的企业需求与服务交易、Upwork的项目/里程碑、Fiverr的标准化服务套餐、Clickworker的居家微任务和技能匹配、Taskrabbit的清晰任务分类。Amazon Mechanical Turk仅作为微任务机制的历史参考：该服务已于2026-09-30关闭，不作为当前可运营竞品。

产品采用“三层任务结构”：企业项目 → 平台任务包 → 个人任务。平台运营端负责拆解、分配、质检和汇总；用户端只显示可做任务、报酬、步骤和验收标准。不能合理独立验收的工作不得强行拆单。

首发分类调整为：AI办公、设计制作、内容创作、数据标注、文字整理、轻量任务。手工协作列为后续验证方向，不在缺少真实企业订单、物流方案和计价标准时开放领取。

每个个人任务都要有固定工作量、交付物、单价、预计耗时、截止时间、资格要求、教程样例、验收指标、修改次数、申诉机制和结算条件。任务来源、资金保障和企业主体核验由平台后台管理，用户无需参与复杂投标。

## 13. 双向需求发布：用户也可以成为需求方

### 产品原则
赚钱 APP 不只是平台单向派发任务。任何有真实需求的个人或企业，都可以提交需求；其他用户完成需求并获得报酬。普通用户端保持简单，不要求需求方理解复杂的项目管理。

### 用户入口
首页任务列表附近增加轻量入口：“你有事情需要别人帮你完成？发布需求”。不增加底部主导航，不打乱“找任务、我的任务、我的收入、我的”四个主要入口。

### 需求提交字段
- 需求标题与类别
- 具体说明、参考示例、交付物
- 预算或预算范围
- 截止日期、交付数量
- 地点/远程要求（适用时）
- 图片、视频、文档等参考附件
- 联系与身份核验信息（后台采集，按最小必要原则）

### 发布审核策略：先审核，再发布
默认流程为“提交草稿 → 自动完整性/风险检查 → 平台人工审核 → 补充资料或核价 → 确认预算和交付标准 → 转成任务/任务包 → 正式发布”。
不能让用户提交内容后直接公开进入任务大厅。审核通过前仅提交者和授权运营人员可见。

自动审核可负责字段缺失、敏感信息、明显违规内容、预算异常、重复需求和格式整理；AI可辅助生成清晰标题、任务说明、拍摄脚本和验收清单，但不得自行编造需求、报酬或授权。人工审核负责主体、真实性、可执行性、预算、版权与安全判断。

### 真人实拍素材专项
新增“真人实拍素材”类别，覆盖：
- 做饭、家务、手工、日常生活等真实过程
- 城市街景、自然环境、指定地点的实拍
- 商品开箱、真实使用过程、体验记录
- 按需求方脚本拍摄的场景、动作和口播
- 其他合法、明确授权的原创素材

每个任务必须明确：拍摄主体、拍摄地点、时长、画幅、分辨率、镜头/动作要求、是否需要露脸/口播、原始素材还是剪辑成片、交付格式、使用平台、商业用途、授权期限、授权地域、是否允许二次剪辑/转授权、报酬与修改次数。

必须取得出镜者的知情同意及可证明的肖像/声音使用授权；涉及他人、住宅、商铺、私人场所或可识别个人信息时，需取得必要许可。禁止偷拍、侵犯隐私、冒用身份、虚假体验、伪造测评、未授权搬运、危险挑战、违法内容和误导性广告。未成年人素材应设置严格限制，不作为普通任务开放。

### 任务发布与验收
需求通过审核后，平台将其转成标准任务商品，展示报酬、数量、资格、拍摄要求、授权范围、验收标准和交付期限。需求方不能在验收时追加未约定的工作；修改次数和退回原因必须可追踪。争议由平台按任务约定和交付证据复核。

### 后台审核队列
- 待初审：检查字段、内容和附件
- 待补充：向需求方提出具体补充项
- 待核价：确认预算能否覆盖创作者报酬、质检、平台服务和风险成本
- 待授权确认：检查肖像、声音、场地、音乐、商标和素材版权许可
- 待发布：审核通过并确认预算/履约保障
- 已发布：进入任务大厅
- 已暂停/拒绝：记录原因、证据和复核入口

### 关键产品决策
默认“人工审核后发布”，不是用户一提交就自动发布。AI负责预审和整理，人工审核控制风险。后续只有在低风险、标准化、已验证的任务类型中，才考虑规则化快速通道；真人实拍、商业广告、涉及第三方肖像或场地的任务始终保留必要的人工审核。


## 14. 商业模式、平台抽佣与用户端极简原则

### 两条业务线必须分账核算

**A. 平台自营/项目承包订单（核心利润）**
- 平台与工厂/企业签完整交付合同，平台对交付结果、质量、进度和售后负责。
- 平台报价是项目总价；平台自行决定任务拆分、人员报酬和质检安排。
- 示例：客户支付100元，执行人员报酬70元，直接质检/物流/支付等可变成本另计。剩余30元只是订单毛利，不是净利润。
- 不要求对工人公开平台采购价或内部利润，但必须如实展示其本人任务报酬、工作量、验收条件、修改次数和结算时间；不得隐瞒其报酬中的扣款。
- 平台承包订单的利润由平台承担获客、管理、履约、返工和坏账风险后取得。

**B. 用户自主发布需求（撮合服务收入）**
- 需求方填写预算和需求；平台审核后决定是否受理、核价、发布。
- 试运营建议：需求方承担单独列明的平台服务费，先以订单执行预算的8%作为测试参数（可设最低服务费，最终以真实支付成本和转化率校准）；接单者拿到订单页面约定的完整报酬。
- 支付前必须展示：执行预算、平台服务费、支付通道费用（如需单列）、订单总额、接单者实际到账金额。未经确认不得追加费用。
- 不采用“用户看到100元、接单者后台只拿90元”的隐性抽佣。也不同时向供需双方重复收费，除非未来经过明确实验和规则公示。
- 若需求方预算不足以覆盖创作者报酬、审核、客服、争议处理及支付成本，则拒绝发布、建议调整预算或改为平台报价的承包订单。

### 定价与单位经济模型
每笔订单必须计算：
- 客户实付收入（不含代收代付资金）
- 接单者/供应商报酬
- 质检与返工成本
- 物流、材料、包装成本
- 支付通道成本
- 客服、审核和争议处理的可变成本
- 退款、坏账和风险准备
- 平台贡献毛利

公式：
- 自营订单贡献毛利 = 客户不含税收入 − 执行报酬 − 质检/物流/材料/支付等直接成本 − 退款坏账准备。
- 撮合订单贡献毛利 = 平台服务费收入 − 支付/审核/客服/争议等直接成本。
- 月度盈亏平衡订单量 = 月固定运营成本 ÷ 单笔平均贡献毛利。

例如100元订单、70元执行报酬、30元表面差额，若质检4元、物流/材料5元、支付与退款风险2元，订单贡献毛利仅19元，且尚未扣除固定员工工资、服务器、办公、税费和获客成本。不能把30%差价直接称为净利润。

### 成本中心
建立独立成本科目：企业销售与BD、任务审核、质检与返工、客服与争议、物流与材料、服务器/数据库/对象存储/CDN、短信/实名核验/风控、支付手续费、财税与法务、办公和人员工资。每月按订单类别统计，不用一个笼统“平台成本”掩盖亏损业务。

### 用户端极简
- 不增加“商业模式”“平台抽佣”“企业管理”等用户端复杂入口。
- 保留现有四个底部入口：找任务、我的任务、我的收入、我的。
- 发布需求只在“我的”中放一个轻量入口，表单采用分步/渐进展示；首页优先展示可赚钱任务。
- 自营订单和撮合订单在后台用订单类型区分，前端只展示用户必须知道的任务报酬、总价、服务费（需求方付款时）、验收与结算规则。
