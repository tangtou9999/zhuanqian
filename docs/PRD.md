# 赚钱 APP 产品需求文档（PRD）

版本：0.1（启动基线）
定位：居家任务与灵活协作平台
口号：赚钱啦，赚钱啦！想要赚钱，就上赚钱 APP！

## 1. 产品目标
为希望在家获得额外收入的人群提供简单、可信、可理解的任务入口。平台组织任务供给、拆解与分发，用户按能力选择任务，按明确标准交付，经过公平验收后结算。不做传统综合招聘网站，不把求职、简历、职位搜索作为首页主流程。

## 2. 用户角色
- 个人用户：浏览任务、查看要求、领取任务、提交成果、按规则修改、查看收入。
- 企业客户：提交真实业务需求、确认报价与验收标准、验收交付成果。
- 平台运营：企业审核、任务审核、拆单、分发、质检、争议处理、对账。
- 质检/物流协作人员：对适用的线下批量加工任务进行抽检、收发与交接。

## 3. 用户端信息架构
底部固定四个入口：
1. 找任务：首页、任务分类、推荐任务。
2. 我的任务：待开始、进行中、待提交、待验收、待修改、已完成、争议中。
3. 我的收入：待验收金额、待结算金额、可提现金额、收入明细。
4. 我的：技能档案、身份认证、收款方式、帮助客服、安全须知。

任务分类初期：手工加工、AI办公、设计制作、文字整理、音视频、电商协作、数据任务。分类可由后台配置，不在客户端写死。

## 4. 任务详情必须展示
需求方主体及平台核验状态；任务内容、交付物、工作量；计价方式、报酬金额、结算条件；截止时间、预计耗时；所需技能和设备；操作步骤、图文/视频教程；验收标准、抽检规则；可修改次数、修改时限；争议与申诉入口；物流/材料交接说明（仅线下任务）。

## 5. 核心业务状态
草稿 → 平台审核 → 已发布 → 可领取 → 已领取 → 进行中 → 已提交 → 验收中 →（通过→待结算→已结算）/（退回修改→重新提交）/（争议处理）。
任务取消、超时、企业撤单、用户退出均需有独立状态和责任规则。所有状态变化必须记录操作者、时间和原因。

## 6. 企业任务与平台拆单
企业提交需求及样品/资料 → 平台核验主体和需求 → 明确总量、单价、质量标准、交期和资金保障 → 平台评估是否可拆分 → 创建子任务/工序 → 分配合适用户或小组 → 质检 → 汇总交付 → 企业验收 → 结算。
线下加工必须先完成小批量试单，核验单位工时、返工率、运输半径、材料损耗和实际净收入，再决定扩大规模。

## 7. 收入与结算
产品界面区分“预估报酬、待验收、待结算、可提现、已结算”，不得把未验收金额描述成已赚到的钱。平台不自行无资质沉淀或挪用用户资金；支付、托管、结算安排须由专业法律与支付合规评估确定。

## 8. 风险与安全
- 企业实名/主体核验和联系方式验证
- 需求真实性、预算与资金来源核验
- 禁止押金、垫资刷单、拉人头、虚假点赞评论、非法数据采集等任务
- 明示任务报酬、扣款规则和验收标准
- 企业拒收必须给出对应标准及证据
- 设置申诉、复核和人工客服
- 最小化收集个人信息，敏感信息加密并设置权限
- 防止未成年人从事不适宜任务
- 对可能构成劳动关系、劳务关系或承揽关系的模式分别评估，不能用产品名称替代法律判断

## 9. MVP范围
第一版真实业务只选择1-2个可远程验收、低风险、交付标准明确的任务类别（建议先验证PPT/文档整理或商品资料整理）。手工加工先作为后台验证中的候选业务，不在没有企业订单和物流方案时开放给用户。

## 10. MVP验收标准
新用户可在不看教程的情况下找到任务并理解报酬和要求；任务详情关键规则完整展示；领取、提交、退回修改、再次提交、验收、申诉状态闭环；每笔报酬可追溯到企业订单和资金来源；企业不能无理由无限退回；管理员可暂停企业、任务和用户；所有关键操作有审计日志；移动端主流浏览器可用，页面有空状态、错误提示和加载反馈。
